1.What this site is

A Next.js 14 static site with no backend and no database. The catalog is a TypeScript list, the bag lives in each visitor’s browser, checkout hands off to WhatsApp, and admin edits live in browser storage.

2.Viewing & editing

npm install   # once
npm run dev   # preview at http://localhost:3000
npm run lint  # static checks
npm run build # production build (before deploying)

Edit a file, save, and the dev server hot-reloads — check the browser. Deploy via Vercel; no env vars required except the optional admin PIN.

6.Product photos

Until real photography exists, branded placeholder blocks render instead. To go live:

  1. Save JPGs at exactly the paths in each product’s images (in public/products/). Keep 3 per product.
  2. Flip the switch in components/ProductVisual.tsx:9:
const USE_REAL_PHOTOS = false;
// becomes:
const USE_REAL_PHOTOS = true;

Photos use object-contain (no cropping). Portrait orientation suits the card and hero frames best.

7.Home page hero

components/HomeHero.tsx: featured product = FEATURED_SKU (else first item); giant background NARCI text; info strip (SKU, name, tagline, size(s), price — FROM ₹X when multi-size); hero Add to Bag uses the default size. The “More steel” row shows the next 4 products; the manifesto block below is plain copy — edit the words in place. To change the hero piece, change FEATURED_SKU.

8.Shop cards & filters

ShopCatalog.tsx: Category options come from the data itself (unique category values) — rename a category by editing the products. Sort: Featured (catalog order) or Price ↑/↓ on the from-price. ShopCard.tsx enforces uniform heights (title clamped to 2 lines with 2 lines reserved, tagline/specs clamped, footer pinned), so long admin-entered names can’t break the grid. Multi-size cards show FROM ₹X plus a size row; single-size cards show a matching ONE SIZE row.

9.Product detail page

components/ProductDetail.tsx: back-to-shop bar with breadcrumb; gallery (main + 3 thumbnails); size selector that appears only with 2+ sizes (buttons show label · price); qty stepper + Add to Bag; spec list; Related row of 3. Price, bag line and WhatsApp message all use the selected size’s price. The page overlays admin edits onto the built-in snapshot and resets selection when navigating. Admin-added slugs resolve client-side via AdminProductPage.tsx (brief “Loading…” on hard refresh); truly unknown slugs still 404.

10.Bag, coupons, WhatsApp

Bag

Slide-over drawer on every page (CartDrawer.tsx, mounted in layout.tsx:43). Lines keyed by SKU + size; stored per-browser under narci-cart. Prices resolve through the merged catalog, so admin edits apply to bag lines too.

Coupons — lib/coupons.ts

Seeds: NARCI10 (10% off, no minimum) and FLAT500 (₹500 off, min ₹2,000). Percent max 90, flat capped at subtotal, codes case-insensitive. Apply validates first — wrong codes are never stored as “applied”; stale codes (bag below minimum, disabled/deleted) auto-clear. Manage codes in /admin → Coupons.

WhatsApp handoff — lib/whatsapp.ts

Set the number: lib/whatsapp.ts:5 — digits only with country code, e.g. 919876543210. Footer and contact buttons reuse it.
export const WHATSAPP_PHONE = "15555555555";
// becomes, e.g.:
export const WHATSAPP_PHONE = "919876543210";

Message format (size per line; coupon block only when valid):

Hi NARCI, I'd like to order: - NARCI-004 (M) x2 — Pit Wall Number Plate — ₹6,800 Subtotal: ₹6,800 Coupon: NARCI10 (−₹680) Total: ₹6,120

Contact form & currency

The form opens the visitor’s mail app to studio@narci.example — update it in ContactForm.tsx:17 and contact/page.tsx:42–47. No server delivery exists. Currency: lib/format.ts (en-IN/INR/zero decimals) covers the whole site.

11.Admin console (/admin)

app/admin/page.tsx → components/AdminConsole.tsx (noindex). Tabs: products, coupons, orders.

Entry gate

PIN screen, session-only. Default narci123; set NEXT_PUBLIC_ADMIN_PIN in Vercel env vars + redeploy for a real one. This is a UI gate, not real security.

# Vercel → Project Settings → Environment Variables
NEXT_PUBLIC_ADMIN_PIN=your-pin-here

Products tab

View / Edit / Delete per row, + New product, Reset defaults. SKU is locked after creation (delete + recreate to change it). Slug auto-generates from the name; category is free text (new values appear in the shop filter). Sizes editor: one row per variant with its own label + price; single-size = one ONE SIZE row. Validation: name/SKU/price required, ≥1 labelled size, unique SKU/slug.

Coupons & orders tabs

Coupons: add code + type + value + optional minimum, Enable/Disable, Delete, Reset defaults. Orders: no server orders exist — sales arrive as WhatsApp chats. The tab shows a local log (this browser, last 50) of each handoff with lines, sizes, coupon and totals.

LocalStorage caveat: admin edits live only in the browser where made (keys narci-admin-products-v1, narci-coupons-v1, narci-order-log-v1; bag: narci-cart). Invisible on other devices/incognito; clearing site data wipes them. Until a CMS backend exists, make edits in the demo browser and treat data/products.ts as canonical.

12.Look & feel

Brand tokens live in two files — keep them in sync. Bone = background, ink = text/borders, blood = accents (active tab, discounts, CTAs).

// tailwind.config.ts → classes like bg-bone, text-ink, bg-blood
bone: "#F2EFEA",  ink: "#0A0A0A",  blood: "#C81D25"
// app/globals.css :root — same three values as CSS variables

Fonts (app/layout.tsx:9–18): Archivo Black display (font-display), Inter body (font-sans). Signature rules in globals.css: zero radius, blood-on-bone selection, arrow cursor on copy with I-beam only in inputs, hard ink focus outline. Motion (hero entrance, drawer slide) uses local timing constants via framer-motion.

13.Safe vs ask-a-developer

Safe to touch

Product fields & FEATURED_SKU · hero/manifesto/about copy · contact copy/links · nav labels/links · footer tagline/links · brand hexes + fonts · WhatsApp number, email, Instagram · seed coupons · cursor/selection CSS

Ask a developer

Checkout math & message building · coupon validation · cart line keys (SKU + size) · AdminProductPage resolution · routing/metadata · localStorage→CMS migration · newsletter backend · catalog sanitizers

14.Troubleshooting

Order goes nowhere / wrong number
WHATSAPP_PHONE still placeholder — set a real digits-only number (see §10).
New admin product 404s on another device
Admin edits are per-browser localStorage. Use the demo browser; long-term, add a backend (§11).
New size not selectable
Every size row needs a label; the detail page resets selection when sizes change (§9).
Coupon rejected
Typo, disabled/deleted code, or bag below minSubtotal — check /admin → Coupons (§10).
Duplicate-looking shop categories
Category spelling differs between products — unify the string (§8).
Stale prices after admin edits
Different browser, or cached static page — same browser, hard refresh, rebuild/redeploy.
Demo PIN hint visible publicly
NEXT_PUBLIC_ADMIN_PIN unset — set it and redeploy (§11).
Newsletter Join does nothing
Placeholder handler — wire a provider or remove the form (§4).

Glossary

Component
Reusable UI block (components/). Pages compose them.
Route
A URL. Folder under app/ = segment; page.tsx renders it; [slug] matches any product URL.
localStorage
Per-browser storage on the visitor’s device. Survives reloads; invisible to other devices and the server.
SSG
Static generation — pages pre-rendered at build time. The 5 built-ins pre-render; admin items resolve in-browser.
Noindex
Search engines told not to list /admin.
Slug
URL-safe product id (framed-katana → /shop/framed-katana).
SKU
Permanent product code shown to buyers and staff.
